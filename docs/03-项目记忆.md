## 关键设计模式

### 1. 模板系统

- **定义方式**：YAML格式定义任务计划模板
- **结构层次**：Phase（阶段）→ Task（任务）→ DAG（依赖关系）
- **匹配算法**：`0.7 * semantic_similarity + 0.3 * keyword_match × historical_success_rate_bonus`
- **版本管理**：支持模板版本控制和灰度发布
- **成功率追踪**：记录历史执行成功率，用于模板优化推荐

### 2. 代理-代理职业体系

- **职业等级**：Junior → Intermediate → Senior → Expert
- **技能掌握度**：1-10级评分
- **经验值系统**：完成任务获得经验，升级解锁新能力
- **晋升路径**：清晰的成长路线和能力边界
- **预定义角色**：admin, project_manager, developer, tester, viewer

## 安全设计

### 认证授权

- **认证方式**：OAuth2 + JWT (HS256)
- **Token管理**：Access Token (15分钟) + Refresh Token (7天)
- **密码安全**：bcrypt哈希，动态成本因子
- **防护措施**：暴力破解防护（5次错误锁定15分钟）、速率限制（100次/分钟）

### 权限模型

- **模型类型**：RBAC（基于角色的访问控制）
- **预定义角色**：admin, project_manager, developer, tester, viewer
- **权限类型**：菜单权限 + 操作权限 + 数据权限
- **权限缓存**：LRU缓存，5分钟过期

## 多智能体协同工作模式

### 组织架构

项目采用**三组织协同**模式，每个组织由专门模型承担角色：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          multi-agent-flow 组织架构                           │
├─────────────────┬─────────────────┬─────────────────┬─────────────────────────┤
│    技术评审组    │     测试组       │     开发组      │      模型配置说明       │
├─────────────────┼─────────────────┼─────────────────┼─────────────────────────┤
│  架构师A        │   测试员         │  开发工程师      │  优先：用户配置模型      │
│  架构师B        │   QA            │  单元测试工程师   │  备用：workbuddy预制模型 │
└─────────────────┴─────────────────┴─────────────────┴─────────────────────────┘
```

### 1. 技术评审组

**人员配置**：2名架构师

**核心职责**：
- 方案可行性评审
- 官方文档对方案实现支持情况验证
- 关键技术点可行性验证

**工作原则**：
> ⚠️ **严禁猜测、臆想、欺骗**
> 
> 对于关键技术点，**必须通过简单测试代码验证方案是否可行**

**输出物**：
- 技术方案评审报告
- 关键技术点验证代码及结果
- 风险识别与应对建议

---

### 2. 测试组

**人员配置**：测试员 + QA

**测试员职责**：
- 基于需求设计测试用例
- 执行测试用例
- 记录测试结果

**QA职责**：
- 基于验证标准评判测试结果
- 对测试执行结果做客观评判

**测试用例标准**：
每个测试用例必须明确包含：
| 要素 | 说明 |
|------|------|
| **对应需求** | 该用例验证的具体需求点 |
| **测试目的** | 为什么要做这个测试 |
| **应用场景** | 测试的业务场景描述 |
| **输入** | 测试输入数据/条件 |
| **输出** | 预期输出结果 |
| **结果验证标准** | 如何判定测试通过/失败的具体标准 |

**反馈原则**：
> ⚠️ **必须严格、如实、悲观地反馈测试结果**
> 
> 不放过任何潜在问题，不美化测试结果

---

### 3. 开发组

**人员配置**：开发工程师 + 单元测试工程师

**开发工程师职责**：
- 负责前后端开发
- 负责部署工作
- 代码实现与优化

**单元测试工程师职责**：
- 对开发的代码**每个函数**做单元测试
- 如实反馈单元测试结果
- 确保测试覆盖率

**交付标准**：
> ⚠️ **要求单元测试全部通过，不遗留任何问题**
> 
> 每个函数都必须有对应的单元测试，且测试通过

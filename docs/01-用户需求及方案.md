### 1. 任务数据模型设计

```python
class TaskType(str, Enum):
    FIXED = "fixed"        # 固定任务
    DYNAMIC = "dynamic"    # 动态任务

class TaskStatus(str, Enum):
    PENDING = "pending"           # 待执行
    IN_PROGRESS = "in_progress"   # 执行中
    REVIEWING = "reviewing"       # 评审中
    APPROVED = "approved"         # 评审通过
    REJECTED = "rejected"         # 评审驳回
    COMPLETED = "completed"       # 已完成
    FAILED = "failed"             # 执行失败

class Task(BaseModel):
    id: str                           # 任务ID
    template_id: Optional[str]        # 关联模板ID（固定任务有，动态任务无）
    parent_task_id: Optional[str]     # 父任务ID（支持子任务）
    name: str                         # 任务名称
    description: str                  # 任务描述
    task_type: TaskType               # 任务类型
    status: TaskStatus                # 任务状态
    
    # 输入输出
    input_data: dict                  # 任务输入数据
    output_data: Optional[dict]       # 任务输出数据
    requirements: list[str]           # 任务要求列表
    
    # 动态任务特有字段
    decomposition_basis: Optional[str] # 分解依据（仅动态任务）
    
    # 验收标准
    acceptance_criteria: list[str]    # 验收标准列表
    review_status: Optional[bool]     # 评审状态（None=未评审，True=通过，False=驳回）
    review_comments: Optional[str]    # 评审意见
    
    # 执行控制
    parallel_group: Optional[str]     # 并行组标识（同组任务可并行）
    dependencies: list[str]           # 依赖任务ID列表
    priority: int                     # 优先级（1-5，1最高）
    
    # Agent相关
    assigned_agent_id: Optional[str]  # 分配的Agent ID
    assigned_roles: list[str]         # 需要的角色列表
    
    # 时间戳
    created_at: datetime
    updated_at: datetime
    started_at: Optional[datetime]
    completed_at: Optional[datetime]
```

### 5. 并行执行机制

```python
class TaskScheduler:
    """任务调度器，支持并行执行"""
    
    async def execute_task_group(self, task_ids: list[str], parallel_group: str):
        """并行执行同组任务"""
        tasks = [self.get_task(tid) for tid in task_ids]
        
        # 检查依赖是否全部完成
        for task in tasks:
            if not self._check_dependencies_completed(task.dependencies):
                raise DependencyNotMetError(f"Task {task.id} dependencies not met")
        
        # 并行执行
        results = await asyncio.gather(
            *[self.execute_single_task(task) for task in tasks],
            return_exceptions=True
        )
        
        return results
    
    def _check_dependencies_completed(self, dependency_ids: list[str]) -> bool:
        """检查依赖任务是否全部完成且通过评审"""
        for dep_id in dependency_ids:
            dep_task = self.get_task(dep_id)
            if dep_task.status != TaskStatus.APPROVED:
                return False
        return True
```

### 6. 评审流程（修正版）

**职责划分**：

| 功能 | Backend | OpenMOSS | 说明 |
|------|---------|----------|------|
| 验收标准定义 | ✅ 主责 | ❌ | 与任务模板关联 |
| 评审流程执行 | ❌ | ✅ 主责 | reviewer角色负责审查 |
| 评审结果记录 | ⚠️ 同步 | ✅ 主责 | OpenMOSS记录，Backend同步 |
| 部分通过逻辑 | ✅ 主责 | ❌ | OpenMOSS仅支持通过/驳回 |
| 评审触发后续任务 | ✅ 主责 | ❌ | Backend负责任务流转 |

**评审流程**：

```
任务完成 → Backend提交评审请求 → OpenMOSS创建评审记录 → reviewer审查
     ↓                                              ↓
Backend同步评审结果 ← OpenMOSS记录审查结果 ← reviewer提交评审
     ↓
Backend判断是否部分通过 → 触发后续任务 / 任务回退
```

**评审标准**：
- 每个验收标准必须明确验证
- 评审组必须基于实际测试结果，严禁猜测
- 评审结果必须如实记录，包含详细评审意见
- 支持部分通过（conditional_approved）

### 8. 动态任务与评审机制设计 (已整改 P0 问题)

#### 8.1 动态任务分解 (Decomposition as a Task)
*   **定义**：在模板中定义 `type: dynamic` 的任务节点。
*   **执行逻辑**：
    1.  Backend 将该任务派发给具有分解能力的 Agent（如 Tech Lead）。
    2.  Agent 根据上下文（前置任务输出）进行思考，输出结构化的子任务列表（如 JSON 格式）。
    3.  **【P0 整改】JSON 容错与重试**：
        *   Backend 接收产出后，尝试解析 JSON。
        *   **解析失败**：Backend 自动将错误信息（如 "JSON 格式错误，请仅返回 JSON 数组"）作为新指令发回给 Agent，要求修正。
        *   **重试限制**：最多重试 3 次。若 3 次仍失败，标记该分解任务为 `failed` 并通知人工介入。
    4.  **解析成功**：Backend 解析 JSON，循环调用 OpenMOSS API 批量创建子任务。
*   **YAML 示例**：
    ```yaml
    - task_id: "dev-breakdown"
      type: dynamic
      target_role: "tech-lead"
      execution_context:
        instruction: "请根据需求文档拆解开发任务，**必须且仅输出合法的 JSON 数组**。"
    ```

#### 8.2 评审检查机制 (Review Gatekeeper)
*   **定义**：在模板中定义 `type: review` 的任务节点，作为 DAG 的关卡。
*   **执行逻辑**：
    1.  前置任务完成后，Backend 创建评审任务派发给 QA/Reviewer Agent。
    2.  Agent 根据 `acceptance_criteria` 进行检查。
    3.  **通过**：Backend 解锁后续依赖任务。
    4.  **【P0 整改】驳回与返工 (Rework)**：
        *   由于 OpenMOSS 不支持将 `done` 状态回退为 `rework`，Backend 采取**创建修正任务**策略。
        *   Backend 创建一个新任务（如 `task_id: "step-1-fix"`），其 `description` 包含原任务产出 + 评审驳回意见。
        *   该修正任务依赖原任务，并指派给原执行 Agent。
        *   修正任务完成后，再次触发评审，直到通过。

#### 8.3 顺序执行与流转 (Backend Scheduler Loop)
*   **机制**：Backend 维护内存 DAG，定时轮询 OpenMOSS 任务状态。
*   **【P0 整改】版本快照机制**：
    *   **问题**：Redis 中仅保留模板最新版本，运行中任务若引用最新模板会导致逻辑不一致。
    *   **方案**：在任务实例化（Instantiation）瞬间，Backend 将当前模板的完整 DAG 定义（JSON 格式）**快照保存**到 PostgreSQL 的 `task_instances` 表中。
    *   **执行**：后续流转逻辑（如依赖检查、Input Mapping）均读取**快照数据**，确保任务流执行过程不受模板更新影响。

#### 8.4 固定任务的文件共享与输入输出 (已整改 P0 问题)
*   **文件共享方案**：采用 **Docker Shared Volume (`/workspace`)**。所有 Agent 容器强制挂载同一共享卷。
*   **输入映射 (`input_mapping`)**：
    *   支持引用前置任务产出：`${task_id.output_path}`。
    *   Backend 解析变量，替换为共享卷中的**绝对路径**（如 `/workspace/task-1/output.csv`）。
    *   **安全限制**：对路径进行白名单校验，防止路径穿越。
*   **输出定义 (`output_definition`)**：
    *   Agent 将产出物写入指定路径。
    *   支持**多文件/目录**：使用 Glob 模式（如 `*.py`）或目录引用。

#### 8.5 Agent 能力与 Skill 统一管理 (已整改 P0 问题)
*   **核心机制**：引入 **`agency-agent` 基座 Skill**，所有 OpenClaw Agent 统一安装。
*   **预装 + 激活**：
    *   **镜像层**：Docker 镜像预装所有标准 Skills（如 `coder`, `reviewer`, `analyst`）。
    *   **运行时**：Agent 领取任务后，`agency-agent` 解析 YAML 中的 `required_skills`，**显式激活**所需 Skill 的上下文。
*   **热重载支持**：利用 OpenClaw 默认的 `skills.load.watch` 机制，新 Skill 加入或变更时自动刷新，无需重启容器。
*   **Backend 职责**：Backend 不再维护能力注册表，仅负责将 YAML 传递给 Agent，由 Agent 自治管理技能加载。

#### 8.6 全链路执行优化 (最终架构定稿)
*   **分级轮询策略 (Tiered Polling)**：
    *   由于 OpenMOSS 不支持 Webhook，Backend 采用分级轮询优化性能。
    *   **Hot (<5min)**：每 2 秒轮询，确保秒级响应。
    *   **Warm (5-30min)**：每 10 秒轮询，平衡负载。
    *   **Cold (>30min)**：每 60 秒轮询，用于长尾监控与超时检测。
*   **Manifest 产出约定**：
    *   强制 Agent 在任务目录生成 `manifest.json`，声明所有产出文件路径。
    *   Backend 通过校验 Manifest 实现结构化提取，避免解析失败。
*   **动态分解批次补偿**：
    *   引入 `batch_id` 记录动态分解产生的子任务集。
    *   若批量派发中途失败，Backend 通过 `batch_id` 进行补偿重试，确保 DAG 最终一致性。

### 9. 数据同步机制

**三层架构**：

| 层级 | 机制 | 频率 | 说明 |
|------|------|------|------|
| 主动同步 | 事件驱动 | 实时 | 任务完成、状态变更、评审结果 |
| 被动同步 | 定时轮询 | 每5分钟 | 状态检查、数据对齐 |
| 缓存层 | Redis | 1-5分钟过期 | 热点数据缓存、查询结果缓存 |

**主动同步示例**：

```python
async def on_task_completed(sub_task_id: str):
    # 1. 从OpenMOSS获取最新状态
    sub_task = await openmoss_client.get_sub_task(sub_task_id)
    
    # 2. 从OpenClaw获取执行结果
    conversation = await openclaw_client.get_conversation(
        sub_task.current_session_id
    )
    
    # 3. 更新Backend数据库
    await backend_db.update_task(
        task_id=sub_task.task_id,
        status="completed",
        output=conversation.output,
        completed_at=datetime.now()
    )
    
    # 4. 清除缓存
    await redis_client.delete(f"task:{sub_task.task_id}")
    
    # 5. 发布事件
    await event_bus.publish("task.completed", {...})
```

#### 2. 意图识别与路由

```python
class IntentRecognizer:
    """意图识别器"""
    
    INTENTS = {
        "create_template": "创建任务模板",
        "update_template": "修改任务模板",
        "create_task": "创建任务",
        "dispatch_task": "派发任务",
        "query_progress": "查询进度",
        "control_task": "控制任务",
        "retry_task": "重试任务",
        "query_template": "查询模板",
    }
    
    async def recognize(self, user_input: str, conversation_history: list) -> dict:
        """识别用户意图"""
        # 调用LLM识别意图
        prompt = f"""
        请识别以下用户输入的意图：
        用户输入：{user_input}
        对话历史：{conversation_history}
        
        可选意图：{list(self.INTENTS.keys())}
        
        返回JSON格式：
        {{
            "intent": "意图名称",
            "parameters": {{参数提取}},
            "confidence": 置信度
        }}
        """
        
        response = await llm_client.complete(prompt)
        return json.loads(response)
```

```python
async def handle_create_task(user_input: str, conversation_history: list):
    """处理创建任务请求"""
    # 1. 识别意图
    intent = await intent_recognizer.recognize(user_input, conversation_history)
    
    # 2. 提取参数
    template_id = intent["parameters"].get("template_id")
    task_parameters = intent["parameters"].get("parameters", {})
    
    # 3. 实例化模板
    task = await template_engine.instantiate(
        template_id=template_id,
        parameters=task_parameters
    )
    
    # 4. 分解任务
    sub_tasks = await task_decomposer.decompose(task)
    
    # 5. 创建OpenMOSS子任务
    for sub_task in sub_tasks:
        await openmoss_client.create_sub_task(sub_task)
    
    # 6. 返回结果
    return {
        "task_id": task.id,
        "sub_tasks": sub_tasks,
        "message": f"任务已创建，ID：{task.id}"
    }
```

```python
async def handle_query_progress(user_input: str, conversation_history: list):
    """处理查询进度请求"""
    # 1. 识别意图
    intent = await intent_recognizer.recognize(user_input, conversation_history)
    
    # 2. 提取任务ID
    task_id = intent["parameters"].get("task_id")
    
    # 3. 查询任务状态
    task = await backend_db.get_task(task_id)
    sub_tasks = await openmoss_client.list_sub_tasks(task_id=task_id)
    
    # 4. 聚合OpenClaw执行结果
    for sub_task in sub_tasks:
        if sub_task.current_session_id:
            conversation = await openclaw_client.get_conversation(
                sub_task.current_session_id
            )
            sub_task.execution_output = conversation.output
    
    # 5. 生成进度报告
    progress_report = generate_progress_report(task, sub_tasks)
    
    return {
        "task_id": task_id,
        "progress": progress_report,
        "message": format_progress_message(progress_report)
    }
```

#### 5. 查询功能设计

```python
@router.get("/api/tasks")
async def list_tasks(
    status: Optional[str] = None,
    priority: Optional[int] = None,
    time_range: Optional[str] = "7d",
    keyword: Optional[str] = None,
    page: int = 1,
    page_size: int = 20
):
    """查询任务列表"""
    query = db.query(Task)
    
    if status:
        query = query.filter(Task.status == status)
    if priority:
        query = query.filter(Task.priority == priority)
    if keyword:
        query = query.filter(Task.name.contains(keyword))
    if time_range:
        start_date = parse_time_range(time_range)
        query = query.filter(Task.created_at >= start_date)
    
    # 分页
    tasks = query.order_by(Task.created_at.desc())\
        .offset((page - 1) * page_size)\
        .limit(page_size)\
        .all()
    
    return {
        "tasks": tasks,
        "total": query.count(),
        "page": page,
        "page_size": page_size
    }
```

#### 6. 控制功能设计

```python
@router.post("/api/tasks/{task_id}/pause")
async def pause_task(task_id: str):
    """暂停任务"""
    task = await backend_db.get_task(task_id)
    if not task:
        raise HTTPException(status_code=404, detail="任务不存在")
    
    # 更新Backend状态
    await backend_db.update_task(task_id, status="paused")
    
    # 通知OpenMOSS暂停子任务
    sub_tasks = await openmoss_client.list_sub_tasks(task_id=task_id)
    for sub_task in sub_tasks:
        if sub_task.status == "in_progress":
            await openmoss_client.block_sub_task(sub_task.id)
    
    return {"message": f"任务{task_id}已暂停"}

@router.post("/api/tasks/{task_id}/retry")
async def retry_task(task_id: str):
    """重试任务"""
    task = await backend_db.get_task(task_id)
    if not task:
        raise HTTPException(status_code=404, detail="任务不存在")
    
    # 重置任务状态
    await backend_db.update_task(
        task_id,
        status="pending",
        retry_count=task.retry_count + 1
    )
    
    # 重新派发任务
    await dispatch_engine.dispatch(task_id)
    
    return {"message": f"任务{task_id}已重新派发"}
```

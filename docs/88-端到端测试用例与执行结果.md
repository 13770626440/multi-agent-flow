## 2. 测试用例设计

### TC-E2E-00: 模板监控到 Agent 创建全流程测试（核心冒烟用例）

| 项目 | 内容 |
|:---|:---|
| **测试目标** | 验证从模板文件变更 → Watchdog 监控 → YAML 解析 → DAG 校验 → Redis 缓存 → AgentProvisioner 触发 → OpenClaw Agent 创建 → OpenMOSS 推送 Agent 信息 → Agent 信息更新的完整链路。 |
| **用例定位** | **核心冒烟测试**，验证系统最核心的模板驱动 Agent 动态供给机制。如果本用例失败，后续用例不应继续执行。 |
| **测试策略** | 在 `template_editor/` 编辑模板，复制到 `template/` 目录触发 Watchdog 监控，验证全链路自动化流程。所有请求严格设置超时（HTTP 10s，Docker 5s）。 |

#### 目录结构说明

| 目录 | 用途 | 是否监控 |
|:---|:---|:---:|
| `根目录/template/` | 存放正式流程模板 YAML 文件 | ✅ 是（Watchdog 实时监控） |
| `根目录/template_editor/` | 存放编辑过程中的模板文件 | ❌ 否（仅编辑，不触发流程） |

#### 2.0.1 测试步骤（带超时控制）

| 步骤 | 操作 | 验证点 | 超时 |
|:---|:---|:---|:---|
| **1** | 在 `template_editor/` 目录创建/编辑 `e2e-smoke-test.yaml` | 文件语法合法，包含 `template_id`、`version`、`roles`、`tasks` 等必需字段 | 5s |
| **2** | 将模板文件复制到 `template/` 目录（触发 Watchdog 监控） | Backend 日志显示模板加载成功，Redis 缓存写入成功 | 10s |
| **3** | 检查 Redis 缓存：`GET template:e2e-smoke-test` | 缓存存在，内容完整 | 5s |
| **4** | 检查 Backend 日志（最近 30 秒） | 包含 `Template e2e-smoke-test loaded successfully` | 10s |
| **5** | 检查 AgentProvisioner 触发日志 | 包含 `ensuring role smoke-test-executor exists` | 15s |
| **6** | 检查 OpenClaw Agent 创建：`GET /api/agents` | 返回 `smoke-test-executor-agent` | 10s |
| **7** | 检查 OpenMOSS Agent 注册：`GET /api/agents` | 返回角色定义，状态为 `active` | 10s |
| **8** | 检查 Cron 配置：`openclaw cron list` | 包含 `smoke-test-executor-poll` | 10s |

#### 2.0.2 测试输入（模板文件）

```yaml
template_id: "e2e-smoke-test"
version: "1.0.0"
description: "端到端冒烟测试模板"

roles:
  smoke-test-executor:
    model: "qwen3.6-plus"
    description: "冒烟测试执行器"

tasks:
  - task_id: "smoke-test-task"
    name: "冒烟测试任务"
    type: fixed
    dependencies: []
    target_role: "smoke-test-executor"
    execution_context:
      instruction: "执行冒烟测试"
      output_format: "text"
```

#### 2.0.4 悲观验收结论

**FAIL 条件**（任一条件触发即判定为失败）：

1. 模板文件 YAML 语法错误，无法解析
2. Backend API 返回非 200 状态码
3. Redis 缓存写入失败
4. Backend 日志无模板加载记录
5. AgentProvisioner 未触发（日志无 `ensuring role` 记录）
6. OpenClaw Agent 创建失败或超时（>10s）
7. OpenMOSS 未接收到 Agent 定义
8. Cron 配置失败
9. 任何步骤超时

**PASS 条件**：

- 所有步骤执行成功，日志显示全链路通畅
- 所有请求在超时时间内完成
- Agent 状态为 `ready`，可在 OpenMOSS 调度中心查询到
- Cron 定时任务已配置

### TC-E2E-01: 完整任务创建与 OpenMOSS 调度链路

| 项目 | 内容 |
|:---|:---|
| **测试目标** | 验证用户指令 -> Agent 意图识别 -> Backend 落盘 -> OpenMOSS 调度子任务 的全链路通畅。 |
| **完整故事线** | 用户发送创建指令 -> Agent 识别意图并提取参数 -> Agent 调用 Backend API -> Backend 写入 DB 并调用 OpenMOSS -> OpenMOSS 返回子任务 ID -> Agent 将结果反馈给用户。 |
| **输入 (模拟人)** | `"帮我创建一个任务，名字叫'用户登录接口开发'，描述是'实现基于 JWT 的登录功能'。"` |
| **预期输出 (Agent)** | 1. 回复：“任务创建成功，任务 ID 为 [Task_ID]。”<br>2. **严禁**：回复模糊（如“好了”）、未提供 ID、或包含 API 原始 JSON 报错。 |
| **数据与日志依据** | 1. **Agent 侧日志**：必须显示 `POST /api/v1/tasks` 调用成功，且提取到 `id`。<br>2. **Backend 日志**：`POST /api/v1/tasks` 返回 200，且日志包含 `Sub-task created` 或相关处理记录。<br>3. **DB 验证**：查询 `task_instances` 表，存在对应记录，`status='pending'`。<br>4. **OpenMOSS 日志**：存在 `POST /api/sub-tasks` 调用记录，返回 200。 |
| **悲观验收结论** | **FAIL 条件**：<br>1. 任何一环日志缺失（如 Backend 成功但 OpenMOSS 未调用）。<br>2. DB 中记录状态异常。<br>3. Agent 回复未包含 Task ID。<br>4. 响应时间 > 15s（视为性能瑕疵）。 |

### TC-E2E-02: 复杂意图识别与多轮对话上下文保持

| 项目 | 内容 |
|:---|:---|
| **测试目标** | 验证 Agent 在多轮对话中能否保持上下文，并处理参数缺失的情况。 |
| **完整故事线** | 用户发送不完整指令 -> Agent 识别缺失参数并引导 -> 用户补充参数 -> Agent 结合上下文再次发起创建请求。 |
| **输入 (模拟人)** | **第一轮**："帮我建个任务。"<br>**Agent 回复**："请提供任务名称和描述。"<br>**第二轮**："叫'支付模块开发'，描述是'对接微信支付'。" |
| **预期输出 (Agent)** | 1. 第一轮回复必须明确询问缺失参数。<br>2. 第二轮回复：“任务‘支付模块开发’创建成功，ID 为 [Task_ID]。” |
| **数据与日志依据** | 1. **Backend 日志**：第一轮对话期间**不应**有 API 调用记录（验证 Agent 未盲目调用）。<br>2. **Agent 侧日志**：第二轮请求中必须正确拼接第一轮获取的参数。 |
| **悲观验收结论** | **FAIL 条件**：<br>1. Agent 在第一轮就尝试调用 API（导致 400 错误）。<br>2. Agent 在第二轮忘记了“创建任务”的意图，转而执行其他操作。<br>3. 任何报错堆栈泄露给用户。 |

### TC-E2E-03: 异常处理与容错机制验证

| 项目 | 内容 |
|:---|:---|
| **测试目标** | 验证当 Backend 服务不可达或 API 报错时，Agent 的反馈是否符合 SKILL.md 定义。 |
| **完整故事线** | 模拟 Backend 宕机（或 Agent 配置错误 URL） -> 用户发送指令 -> Agent 尝试调用失败 -> Agent 捕获异常并按规范回复。 |
| **输入 (模拟人)** | `"查询任务 task_999 的进度。"` (此时 Backend 已停止或 URL 错误) |
| **预期输出 (Agent)** | 1. 回复：“抱歉，任务管理系统暂时无法连接，请稍后再试。”（严格匹配 SKILL.md 定义）。 |
| **数据与日志依据** | 1. **Agent 侧日志**：必须显示 `ConnectionError` 或 `500 Internal Server Error`。<br>2. **Agent 回复**：不能是 Python 报错堆栈，也不能是默认的“我不知道”。 |
| **悲观验收结论** | **FAIL 条件**：<br>1. Agent 回复了技术报错信息（如 `HTTPStatusError`）。<br>2. Agent 长时间无响应（超时未处理异常）。 |

 66f73ad1-20ba-4c94-bcee-a8154cb7773d | 用户登录接口开发 | PENDING | 2026-04-25 06:31:33.691778

### 失败原因分析

1. **Agent 未调用 Backend API**：Agent 虽然在 `tasks/` 目录下创建了本地文件，但没有按照 `multi-agent-flow-manager` Skill 的指引调用 Backend API。
2. **Skill 加载但未被触发**：Skill 已正确加载（`openclaw skills list` 显示 `✓ ready`），但 Agent 可能没有正确识别任务创建意图，或 Skill 中的指令不够明确。
3. **Backend 功能正常**：通过直接 API 调用验证，Backend 任务创建功能正常，数据库表已正确初始化。

### 修复建议

1. 优化 `multi-agent-flow-manager/SKILL.md` 中的指令，明确要求 Agent 在识别到"创建任务"意图时必须调用 Backend API。
2. 在 Agent 环境变量中配置 `BACKEND_BASE_URL=http://maf-backend:8000`。
3. 增加 Agent 调用 Backend API 的示例对话（Few-Shot Examples）。

# 通用项目执行规范 V1.0

> **用途**：定义项目协作流程、角色职责及文档管理规范，确保项目高质量交付。
> **更新规则**：严禁随意修改核心流程，变更需经架构组评审。

***

## 1. 核心原则 (Core Principles)

1. **实测第一，严禁猜想**：涉及第三方库、中间件或关键技术点，必须查阅官方文档或编写 Demo 验证，禁止主观臆断。
2. **悲观谨慎，质量至上**：评审与测试需持悲观态度，穷尽边界条件。评分必须 > 9 分且无 P0/P1 问题方可流转。
3. **严禁跳步，全程追溯**：严格执行七步骤流程，文档间必须保持严格的依赖与双向追溯。
4. **守住边界，严禁越权**：每项任务，每个阶段必须有各独立组完成，严禁越权执行、更改。

***

| 组别       | 角色          | 核心职责                                  | 匹配模型             |

## 3. 七步骤执行流程 (Seven-Step Process)

所有任务必须严格按顺序执行，**主智能体不得跳过任何步骤**。

|   步骤  | 阶段名称     | 执行人      | 核心动作与产出                                | 准出标准                |
| :---: | :------- | :------- | :------------------------------------- | :------------------ |
| **1** | **开发设计** | **开发组**  | 完成详细设计文档（状态：待审核）。主智能体总结汇报。             | 设计文档完整，覆盖需求。        |
| **2** | **架构评审** | **架构组**  | **实测验证**关键技术，检查设计合理性、官方文档一致性。          | 评分 > 9，无 P0/P1。     |
| **3** | **开发实现** | **开发组**  | 编写代码，编写单元测试，执行单测。                      | 代码完成，单测 100% 通过。    |
| **4** | **测试执行** | **测试组**  | 执行集成测试，QA 审计测试报告。                      | 测试用例全覆盖，日志真实。       |
| **5** | **架构验收** | **架构组**  | **一致性检查**（代码 vs 文档 vs 测试），质量审核。        | 评分 > 9，无 P0/P1。     |
| **6** | **用户确认** | **用户**   | 验收最终结果。                                | 用户明确回复“通过/继续”。      |
| **7** | **流转沉淀** | **主智能体** | **六文档同步** -> **Git 提交** -> **最佳实践沉淀**。 | Git Commit 成功，文档一致。 |

***

## 4. 文档管理规范 (Document Standards)

### 4.1 文档依赖图谱

- **00-会议纪要** -> 提取需求 -> **01-用户需求**
- **01-用户需求** -> 分解任务 -> **02-计划执行**
- **02-计划执行** -> 指导设计 -> **04-详细设计**
- **04-详细设计** -> 沉淀经验 -> **05-最佳实践**

### 4.2 更新铁律

1. **追加更新 (Append-Only)**：**严禁覆盖**已有内容。所有更新必须在文件末尾或指定章节后追加。
2. **更新时机**：仅在 **步骤 6（用户确认）** 完成后，**步骤 7（流转）** 开始时执行。
3. **一致性检查**：更新后，必须比对 **代码 vs 文档 vs 测试日志**，确保三者一致。
4. **Git 提交**：文档更新完毕后，必须执行 `git add -A && git commit`。

### 2. 模板加载与校验逻辑 (Template Loader)

**上下文**：`template/` 目录下的 YAML 文件通过 Watchdog 监控，变动时自动加载。

**实现逻辑**：
1.  **文件读取**：读取 YAML 内容。
2.  **Schema 校验**：使用 Pydantic `TemplateSchema` 校验结构。
3.  **DAG 校验**：
    *   构建有向图。
    *   检查是否存在循环依赖 (Cycle Detection)。
    *   检查 `dependencies` 引用的 `task_id` 是否存在。
4.  **缓存更新**：校验通过后，序列化存入 Redis `template:{id}`。

**伪代码**：

```python
class TemplateLoader:
    def on_file_changed(self, file_path):
        try:
            # 1. 解析
            data = yaml.safe_load(open(file_path))
            template = TemplateSchema(**data)
            
            # 2. DAG 校验
            graph = networkx.DiGraph()
            for task in template.tasks:
                graph.add_node(task.task_id)
                for dep in task.dependencies:
                    if dep not in [t.task_id for t in template.tasks]:
                        raise ValueError(f"Dependency {dep} not found")
                    graph.add_edge(dep, task.task_id)
            
            if not networkx.is_directed_acyclic_graph(graph):
                raise ValueError("Circular dependency detected")
            
            # 3. 存入 Redis
            redis.set(f"template:{template.template_id}", json.dumps(template.dict()))
            logger.info(f"Template {template.template_id} loaded successfully")
            
        except Exception as e:
            logger.error(f"Failed to load template: {e}")
```

### 3. 任务实例化与快照 (Instantiation & Snapshot)

**上下文**：用户发起任务，Backend 将模板转化为运行实例。

**实现逻辑**：
1.  **参数注入**：将用户输入填充到 `input_schema`。
2.  **生成快照**：将完整的 DAG 定义（包含所有 Task 的 YAML 结构）序列化为 JSON。
3.  **持久化**：存入 PostgreSQL `task_instances` 表，状态为 `INITIALIZED`。
4.  **初始派发**：查找所有 `dependencies` 为空的任务，状态置为 `READY`，加入调度队列。

**伪代码**：

```python
async def instantiate_task(template_id: str, user_inputs: dict):
    # 1. 获取模板
    tpl_data = redis.get(f"template:{template_id}")
    template = TemplateSchema(**json.loads(tpl_data))
    
    # 2. 创建实例记录
    instance = TaskInstance(
        id=str(uuid4()),
        template_id=template_id,
        inputs=user_inputs,
        dag_snapshot=template.dict(), # 完整快照
        status="INITIALIZED",
        created_at=datetime.now()
    )
    db.add(instance)
    await db.commit()
    
    # 3. 解锁初始任务
    for task in template.tasks:
        if not task.dependencies:
            await scheduler.dispatch_task(instance.id, task.task_id)
```

### 4. Backend 调度循环 (Scheduler Loop)

**上下文**：核心引擎，负责驱动任务流转。

**实现逻辑**：
1.  **轮询**：每 5 秒查询数据库中状态为 `DISPATCHED` 的任务。
2.  **状态同步**：调用 OpenMOSS API 获取最新状态。
3.  **状态机处理**：
    *   **`done`**:
        *   获取产出路径 (`output_path`)。
        *   查找依赖该任务的所有后续任务。
        *   若后续任务的所有前置任务均 `done`，则调用 `dispatch_task`。
    *   **`review_failed`**:
        *   创建修正任务 (`rework_task`)，依赖原任务。
        *   将修正任务加入 DAG 快照。
        *   派发修正任务。
    *   **`failed`**:
        *   标记实例失败，发送告警。
4.  **超时检查**：若 `dispatched_at` 超过 `timeout`，终止任务。

**伪代码**：

```python
async def scheduler_loop():
    while True:
        tasks = db.query(Task).filter(Task.status == "DISPATCHED").all()
        
        for task in tasks:
            # 1. 获取 OpenMOSS 状态
            om_status = await openmoss_client.get_sub_task(task.om_id)
            
            if om_status.status == "done":
                # 2. 解锁后续
                dependents = get_dependents(task)
                for dep in dependents:
                    if are_all_deps_done(dep):
                        await dispatch_task(dep)
                        
            elif om_status.status == "review_failed":
                # 3. 创建修正任务
                rework_task = create_rework_task(task, om_status.comments)
                db.add(rework_task)
                await dispatch_task(rework_task)
        
        await asyncio.sleep(5)
```

### 5. 任务派发与文件隔离 (Dispatch & File Isolation)

**上下文**：将任务发送给 Agent，并处理文件路径。

**实现逻辑**：
1.  **目录准备**：确保 `/data/tasks/{task_id}/` 存在。
2.  **输入解析 (Input Mapping)**：
    *   读取 YAML 中的 `input_mapping`。
    *   解析变量 `${task-A.output}` -> 查询 Task A 的产出路径 `/data/tasks/task-A/output.json`。
    *   **安全校验**：确保路径在 `/data/tasks/` 根目录下。
3.  **Prompt 组装**：
    *   使用 Jinja2 渲染 `execution_context.instruction`，注入解析后的路径。
    *   注入 `required_skills` 列表。
4.  **调用 OpenMOSS**：
    *   `POST /api/sub-tasks`。
    *   `description`: 渲染后的 Prompt。
    *   `assigned_agent`: 匹配到的 Agent ID。

**伪代码**：

```python
async def dispatch_task(instance_id, task_id):
    # 1. 准备目录
    task_dir = f"/data/tasks/{task_id}"
    os.makedirs(task_dir, exist_ok=True)
    
    # 2. 解析输入
    task_def = get_task_def_from_snapshot(instance_id, task_id)
    inputs = {}
    for key, ref in task_def.input_mapping.items():
        path = resolve_path_variable(ref) # e.g., /data/tasks/task-A/output.json
        inputs[key] = path
        
    # 3. 渲染 Prompt
    prompt = render_template(task_def.instruction, inputs=inputs)
    
    # 4. 派发
    await openmoss_client.create_sub_task(
        task_id=task_id,
        description=f"## Skills Required\n{task_def.required_skills}\n\n## Instruction\n{prompt}",
        assigned_agent=match_agent(task_def.target_role)
    )
```

### 6. `agency-agent` Skill 工作流

**上下文**：Agent 侧如何执行任务。

**实现逻辑**：
1.  **接收任务**：Agent 领取任务，读取 `description`。
2.  **解析元数据**：提取 `## Skills Required` 和 `## Instruction`。
3.  **激活技能**：
    *   检查已加载 Skills。
    *   若缺失，从 `/skills` 目录加载（利用 OpenClaw 热重载）。
    *   在 System Prompt 中引入 Skill 上下文。
4.  **执行**：
    *   读取 `Instruction` 中指定的输入路径（如 `/data/tasks/task-A/output.json`）。
    *   执行逻辑。
    *   将结果写入当前工作目录（`./result.json` 即 `/data/tasks/{task_id}/result.json`）。
5.  **提交**：调用 OpenMOSS API 提交任务。
6.  **Manifest 生成**：
    *   **强制约定**：Agent 必须在任务目录下生成 `manifest.json`，声明产出物路径。
    *   格式：`{"outputs": ["result.json", "report.png"]}`。

### 7. 调度循环优化：分级轮询 (Tiered Polling)

**上下文**：解决 OpenMOSS 无 Webhook 导致的轮询压力与延迟问题。

**实现逻辑**：
1.  **优先级队列**：Backend 维护一个 `PriorityQueue`，存储 `(next_check_time, task_id)`。
2.  **动态间隔计算**：
    *   **Hot (<5min)**：`next_check = now + 2s`。
    *   **Warm (5-30min)**：`next_check = now + 10s`。
    *   **Cold (>30min)**：`next_check = now + 60s`。
3.  **批量查询**：每次从队列中取出所有 `next_check_time <= now` 的任务，批量调用 OpenMOSS API 获取状态，减少网络开销。

---

### 8. 动态分解的原子性与补偿机制

**上下文**：确保动态分解产生的子任务集（Batch）要么全部创建，要么最终通过补偿机制补齐。

**实现逻辑**：
1.  **批次记录**：解析 JSON 后，生成 `batch_id`，将所有子任务写入数据库，状态为 `PENDING_CREATE`。
2.  **异步 Worker**：后台 Worker 遍历 `PENDING_CREATE` 任务，逐个调用 OpenMOSS API。
3.  **状态流转**：创建成功则更新为 `DISPATCHED`。
4.  **补偿重试**：若 Worker 中断，重启后扫描 `PENDING_CREATE` 任务并重试，确保**最终一致性**。

### 10. Backend 调度循环逻辑补充

Backend 启动后台定时任务（每 5 秒），执行以下逻辑：

1.  **加载快照**：从数据库读取当前运行中任务的 DAG 快照。
2.  **轮询状态**：
    *   遍历所有状态为 `DISPATCHED` 的任务 ID。
    *   调用 OpenMOSS API `GET /api/sub-tasks/{id}` 获取最新状态。
3.  **状态处理**：
    *   **Case: `done`**
        *   获取产出路径 (`output_path`)。
        *   **解锁后续**：查找依赖该任务的所有后续任务。
        *   **依赖检查**：若后续任务的所有前置任务均 `done`，则将其状态更新为 `READY`。
        *   **数据注入**：解析后续任务的 `input_mapping`，替换变量为实际路径。
        *   **派发**：调用 OpenMOSS API 创建后续任务。
    *   **Case: `review` (评审通过)**
        *   同 `done` 逻辑，解锁后续。
    *   **Case: `review_failed` (评审驳回)**
        *   **创建修正任务**：生成新任务 ID（如 `step-1-fix`），依赖原任务，Description 包含驳回意见。
        *   将修正任务加入 DAG。
    *   **Case: `failed`**
        *   标记整个任务流失败，发送告警。
4.  **超时检查**：
    *   检查 `DISPATCHED` 任务的运行时间，若超过 `timeout`，调用 OpenMOSS API 终止任务并标记失败。

### 11. `agency-agent` Skill 工作流补充

所有 Agent 容器预装 `agency-agent`，其 `SKILL.md` 定义如下工作流：

1.  **接收任务**：Agent 从 OpenMOSS 领取任务，读取 `description`（包含 YAML 片段）。
2.  **解析需求**：
    *   提取 `required_skills` 列表。
    *   提取 `execution_context` 中的指令。
3.  **激活技能**：
    *   检查自身已加载的 Skills。
    *   若缺少所需 Skill，尝试从 `/skills` 目录加载（利用 OpenClaw 热重载）。
    *   在 System Prompt 中引入所需 Skill 的上下文。
4.  **执行任务**：
    *   读取 `input_mapping` 指定的文件路径（从 `/workspace` 读取）。
    *   执行指令。
5.  **提交结果**：
    *   将产出物写入 `output_definition` 指定的路径。
    *   调用 OpenMOSS API 提交任务。

### 3. 关键设计点详解

#### 3.1 推拉结合派发机制 (Push-Pull Dispatch)

**设计背景**：OpenClaw API 可能存在不稳定性，单一推送模式存在单点故障风险。

**实现方案**：
```python
class Dispatcher:
    async def dispatch_task(self, sub_task: SubTaskRecord):
        """派发任务：主推 + 备拉双保险"""
        try:
            # 1. 主推模式：实时调用 OpenClaw API
            await self.push_to_openclaw(sub_task)
            sub_task.dispatch_status = "pushed"
        except Exception as e:
            logger.warning(f"OpenClaw API 失败，降级为 Pull 模式: {e}")
            # 2. 备拉模式：仅更新 OpenMOSS 状态，等待 Agent 轮询
            await self.pull_fallback(sub_task)
            sub_task.dispatch_status = "pending_pull"
        
        # 3. 记录派发日志
        await self.log_dispatch(sub_task)

    async def push_to_openclaw(self, sub_task: SubTaskRecord):
        """主推：调用 OpenClaw 消息注入 API"""
        async with httpx.AsyncClient() as client:
            response = await client.post(
                f"{settings.OPENCLAW_BASE_URL}/api/v1/message",
                headers={"Authorization": f"Bearer {self.token_manager.get_token('gateway')}"},
                json={
                    "channel": "api",
                    "message": sub_task.instruction,
                    "conversation_id": sub_task.conversation_id,
                    "wait_for_response": False  # 异步模式
                },
                timeout=10.0
            )
            response.raise_for_status()

    async def pull_fallback(self, sub_task: SubTaskRecord):
        """备拉：在 OpenMOSS 中标记任务，等待 Agent 轮询"""
        await self.openmoss_client.update_sub_task(
            sub_task.openmoss_id,
            status="assigned",
            assigned_agent=sub_task.role
        )
```

**关键优势**：
- **高可用**：即使 OpenClaw API 宕机，任务也不会丢失。
- **最终一致性**：Agent 的 Cron 脚本（每 5 分钟）会自动拉取 `assigned` 状态的任务。
- **会话隔离**：每个子任务使用独立 `conversation_id`，避免上下文混乱。

#### 3.2 TokenManager 多凭证管理

**设计背景**：系统需要管理 Planner/Executor/Reviewer/Patrol/Gateway 五种 Token，硬编码易出错。

**实现方案**：

class TokenManager:
    """集中式 Token 管理器"""
    
    def __init__(self):
        self._tokens = {
            "planner": os.getenv("OPENMOSS_PLANNER_TOKEN"),
            "executor": os.getenv("OPENMOSS_EXECUTOR_TOKEN"),
            "reviewer": os.getenv("OPENMOSS_REVIEWER_TOKEN"),
            "patrol": os.getenv("OPENMOSS_PATROL_TOKEN"),
            "gateway": os.getenv("OPENCLAW_GATEWAY_TOKEN"),
        }
        self._lock = asyncio.Lock()
    
    def get_token(self, role: str) -> str:
        """获取指定角色的 Token"""
        token = self._tokens.get(role)
        if not token:
            raise ValueError(f"Token for role '{role}' not configured")
        return token
    
    async def refresh_token(self, role: str, new_token: str):
        """热更新 Token（无需重启服务）"""
        async with self._lock:
            self._tokens[role] = new_token
            logger.info(f"Token refreshed for role: {role}")

#### 3.3 DAG 引擎与依赖管理

**设计背景**：任务之间存在依赖关系，需要确保按正确顺序执行。

**实现方案**：
```python
class DAGEngine:
    """基于 networkx 的 DAG 依赖引擎"""
    
    def __init__(self, tasks: List[SubTaskRecord]):
        self.graph = nx.DiGraph()
        for task in tasks:
            self.graph.add_node(task.id)
            for dep_id in task.dependencies:
                self.graph.add_edge(dep_id, task.id)
        
        # 校验是否为有效 DAG
        if not nx.is_directed_acyclic_graph(self.graph):
            raise ValueError("Circular dependency detected")
    
    def get_ready_tasks(self, completed_tasks: Set[str]) -> List[str]:
        """获取当前可执行的任务（所有依赖已完成）"""
        ready = []
        for task_id in self.graph.nodes():
            if task_id in completed_tasks:
                continue
            predecessors = set(self.graph.predecessors(task_id))
            if predecessors.issubset(completed_tasks):
                ready.append(task_id)
        return ready
    
    def get_execution_order(self) -> List[str]:
        """获取拓扑排序后的执行顺序"""
        return list(nx.topological_sort(self.graph))
```

#### 3.4 异常处理与重试机制

**设计背景**：网络波动、API 限流、Agent 繁忙等异常情况需要妥善处理。

**实现方案**：
```python
from tenacity import retry, stop_after_attempt, wait_exponential

class ErrorHandler:
    """异常处理与重试引擎"""
    
    @retry(
        stop=stop_after_attempt(3),
        wait=wait_exponential(multiplier=2, min=2, max=8),
        reraise=True
    )
    async def dispatch_with_retry(self, sub_task: SubTaskRecord):
        """带重试的派发（指数退避：2s → 4s → 8s）"""
        await self.dispatcher.dispatch_task(sub_task)
    
    async def handle_task_failure(self, sub_task: SubTaskRecord, error: Exception):
        """任务失败处理"""
        sub_task.retry_count += 1
        
        if sub_task.retry_count >= settings.MAX_RETRIES:
            # 超过重试上限，标记为 blocked
            sub_task.status = "blocked"
            await self.notifier.alert_admin(
                f"Task {sub_task.id} failed after {sub_task.retry_count} retries: {error}"
            )
        else:
            # 重新加入队列
            await self.retry_queue.put(sub_task)
```

**重试策略**：
| 重试次数 | 等待时间 | 说明 |
|:---:|:---:|:---|
| 1 | 2 秒 | 瞬时网络波动 |
| 2 | 4 秒 | API 短暂限流 |
| 3 | 8 秒 | Agent 繁忙 |
| >3 | - | 标记 `blocked`，通知人工介入 |

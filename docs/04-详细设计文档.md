### 2. 模板加载与校验逻辑 (Template Loader)

**上下文**：`template/` 目录下的 YAML 文件通过 Watchdog 监控，变动时自动加载。

**实现逻辑**：
1.  **文件读取**：读取 YAML 内容。
2.  **Schema 校验**：使用 Pydantic `TemplateSchema` 校验结构。
3.  **DAG 校验**：
    *   构建有向图。
    *   检查是否存在循环依赖 (Cycle Detection)。
    *   检查 `dependencies` 引用的 `task_id` 是否存在。
4.  **缓存更新**：校验通过后，序列化存入 Redis `template:{id}`。

**伪代码**：

```python
class TemplateLoader:
    def on_file_changed(self, file_path):
        try:
            # 1. 解析
            data = yaml.safe_load(open(file_path))
            template = TemplateSchema(**data)
            
            # 2. DAG 校验
            graph = networkx.DiGraph()
            for task in template.tasks:
                graph.add_node(task.task_id)
                for dep in task.dependencies:
                    if dep not in [t.task_id for t in template.tasks]:
                        raise ValueError(f"Dependency {dep} not found")
                    graph.add_edge(dep, task.task_id)
            
            if not networkx.is_directed_acyclic_graph(graph):
                raise ValueError("Circular dependency detected")
            
            # 3. 存入 Redis
            redis.set(f"template:{template.template_id}", json.dumps(template.dict()))
            logger.info(f"Template {template.template_id} loaded successfully")
            
        except Exception as e:
            logger.error(f"Failed to load template: {e}")
```

### 3. 任务实例化与快照 (Instantiation & Snapshot)

**上下文**：用户发起任务，Backend 将模板转化为运行实例。

**实现逻辑**：
1.  **参数注入**：将用户输入填充到 `input_schema`。
2.  **生成快照**：将完整的 DAG 定义（包含所有 Task 的 YAML 结构）序列化为 JSON。
3.  **持久化**：存入 PostgreSQL `task_instances` 表，状态为 `INITIALIZED`。
4.  **初始派发**：查找所有 `dependencies` 为空的任务，状态置为 `READY`，加入调度队列。

**伪代码**：

```python
async def instantiate_task(template_id: str, user_inputs: dict):
    # 1. 获取模板
    tpl_data = redis.get(f"template:{template_id}")
    template = TemplateSchema(**json.loads(tpl_data))
    
    # 2. 创建实例记录
    instance = TaskInstance(
        id=str(uuid4()),
        template_id=template_id,
        inputs=user_inputs,
        dag_snapshot=template.dict(), # 完整快照
        status="INITIALIZED",
        created_at=datetime.now()
    )
    db.add(instance)
    await db.commit()
    
    # 3. 解锁初始任务
    for task in template.tasks:
        if not task.dependencies:
            await scheduler.dispatch_task(instance.id, task.task_id)
```

### 4. Backend 调度循环 (Scheduler Loop)

**上下文**：核心引擎，负责驱动任务流转。

**实现逻辑**：
1.  **轮询**：每 5 秒查询数据库中状态为 `DISPATCHED` 的任务。
2.  **状态同步**：调用 OpenMOSS API 获取最新状态。
3.  **状态机处理**：
    *   **`done`**:
        *   获取产出路径 (`output_path`)。
        *   查找依赖该任务的所有后续任务。
        *   若后续任务的所有前置任务均 `done`，则调用 `dispatch_task`。
    *   **`review_failed`**:
        *   创建修正任务 (`rework_task`)，依赖原任务。
        *   将修正任务加入 DAG 快照。
        *   派发修正任务。
    *   **`failed`**:
        *   标记实例失败，发送告警。
4.  **超时检查**：若 `dispatched_at` 超过 `timeout`，终止任务。

**伪代码**：

```python
async def scheduler_loop():
    while True:
        tasks = db.query(Task).filter(Task.status == "DISPATCHED").all()
        
        for task in tasks:
            # 1. 获取 OpenMOSS 状态
            om_status = await openmoss_client.get_sub_task(task.om_id)
            
            if om_status.status == "done":
                # 2. 解锁后续
                dependents = get_dependents(task)
                for dep in dependents:
                    if are_all_deps_done(dep):
                        await dispatch_task(dep)
                        
            elif om_status.status == "review_failed":
                # 3. 创建修正任务
                rework_task = create_rework_task(task, om_status.comments)
                db.add(rework_task)
                await dispatch_task(rework_task)
        
        await asyncio.sleep(5)
```

### 5. 任务派发与文件隔离 (Dispatch & File Isolation)

**上下文**：将任务发送给 Agent，并处理文件路径。

**实现逻辑**：
1.  **目录准备**：确保 `/data/tasks/{task_id}/` 存在。
2.  **输入解析 (Input Mapping)**：
    *   读取 YAML 中的 `input_mapping`。
    *   解析变量 `${task-A.output}` -> 查询 Task A 的产出路径 `/data/tasks/task-A/output.json`。
    *   **安全校验**：确保路径在 `/data/tasks/` 根目录下。
3.  **Prompt 组装**：
    *   使用 Jinja2 渲染 `execution_context.instruction`，注入解析后的路径。
    *   注入 `required_skills` 列表。
4.  **调用 OpenMOSS**：
    *   `POST /api/sub-tasks`。
    *   `description`: 渲染后的 Prompt。
    *   `assigned_agent`: 匹配到的 Agent ID。

**伪代码**：

```python
async def dispatch_task(instance_id, task_id):
    # 1. 准备目录
    task_dir = f"/data/tasks/{task_id}"
    os.makedirs(task_dir, exist_ok=True)
    
    # 2. 解析输入
    task_def = get_task_def_from_snapshot(instance_id, task_id)
    inputs = {}
    for key, ref in task_def.input_mapping.items():
        path = resolve_path_variable(ref) # e.g., /data/tasks/task-A/output.json
        inputs[key] = path
        
    # 3. 渲染 Prompt
    prompt = render_template(task_def.instruction, inputs=inputs)
    
    # 4. 派发
    await openmoss_client.create_sub_task(
        task_id=task_id,
        description=f"## Skills Required\n{task_def.required_skills}\n\n## Instruction\n{prompt}",
        assigned_agent=match_agent(task_def.target_role)
    )
```

### 1. 通用任务模板 YAML Schema (完整版)

```yaml
template_id: "universal-task-flow"
version: "1.0.0"
description: "通用任务流程模板"

# 1. 全局输入定义 (实例化时必填)
input_schema:
  data_source: 
    type: string
    required: true
    description: "数据源 URL 或文件路径"
  report_format: 
    type: string
    default: "markdown"
    description: "报告输出格式"

# 2. 任务节点定义
tasks:
  - task_id: "step-1-data-collection"
    name: "数据收集与清洗"
    type: fixed # fixed / dynamic / review
    
    # 前置依赖 (DAG 控制)
    dependencies: []
    
    # 角色与能力要求
    target_role: "data-engineer"
    required_capabilities: ["web_scraping", "data_cleaning"]
    required_skills: ["scraper-tool", "pandas-expert"] # 声明所需 Skill
    
    # 执行上下文 (映射为 OpenMOSS 的 description)
    execution_context:
      instruction: "请从指定数据源抓取数据，清洗无效值，并输出为 JSON 格式。"
      input_mapping:
        source: "${input.data_source}" # 引用全局输入
      output_format: "json"
    
    # 输出定义
    output_definition:
      type: "file"
      format: "json"
      path: "/workspace/step-1/output.json" # 写入共享卷路径

    # 验收标准
    acceptance_criteria:
      - "输出合法的 JSON 数据"
      - "数据条目数大于 100"
    
    # 执行控制
    control:
      timeout: 300 # 秒
      retry_policy:
        max_retries: 2
```

### 2. Backend 调度循环 (Scheduler Loop) 逻辑

Backend 启动后台定时任务（每 5 秒），执行以下逻辑：

1.  **加载快照**：从数据库读取当前运行中任务的 DAG 快照。
2.  **轮询状态**：
    *   遍历所有状态为 `DISPATCHED` 的任务 ID。
    *   调用 OpenMOSS API `GET /api/sub-tasks/{id}` 获取最新状态。
3.  **状态处理**：
    *   **Case: `done`**
        *   获取产出路径 (`output_path`)。
        *   **解锁后续**：查找依赖该任务的所有后续任务。
        *   **依赖检查**：若后续任务的所有前置任务均 `done`，则将其状态更新为 `READY`。
        *   **数据注入**：解析后续任务的 `input_mapping`，替换变量为实际路径。
        *   **派发**：调用 OpenMOSS API 创建后续任务。
    *   **Case: `review` (评审通过)**
        *   同 `done` 逻辑，解锁后续。
    *   **Case: `review_failed` (评审驳回)**
        *   **创建修正任务**：生成新任务 ID（如 `step-1-fix`），依赖原任务，Description 包含驳回意见。
        *   将修正任务加入 DAG。
    *   **Case: `failed`**
        *   标记整个任务流失败，发送告警。
4.  **超时检查**：
    *   检查 `DISPATCHED` 任务的运行时间，若超过 `timeout`，调用 OpenMOSS API 终止任务并标记失败。

### 3. `agency-agent` Skill 工作流

所有 Agent 容器预装 `agency-agent`，其 `SKILL.md` 定义如下工作流：

1.  **接收任务**：Agent 从 OpenMOSS 领取任务，读取 `description`（包含 YAML 片段）。
2.  **解析需求**：
    *   提取 `required_skills` 列表。
    *   提取 `execution_context` 中的指令。
3.  **激活技能**：
    *   检查自身已加载的 Skills。
    *   若缺少所需 Skill，尝试从 `/skills` 目录加载（利用 OpenClaw 热重载）。
    *   在 System Prompt 中引入所需 Skill 的上下文。
4.  **执行任务**：
    *   读取 `input_mapping` 指定的文件路径（从 `/workspace` 读取）。
    *   执行指令。
5.  **提交结果**：
    *   将产出物写入 `output_definition` 指定的路径。
    *   调用 OpenMOSS API 提交任务。

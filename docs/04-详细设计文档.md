### 2. 模板加载与校验逻辑

**上下文**：`template/` 目录下的 YAML 文件通过 Watchdog 监控，变动时自动加载。

**实现逻辑**：
1.  **文件读取**：读取 YAML 内容。
2.  **时间戳设置**：设置 `created_at/updated_at` 为 `datetime.now()`（保持 datetime 类型，与 TemplateSchema 定义一致）。
3.  **Schema 校验**：使用 Pydantic `TemplateSchema` 校验结构。
4.  **DAG 校验**：
    *   构建有向图。
    *   检查是否存在循环依赖 (Cycle Detection)。
    *   检查 `dependencies` 引用的 `task_id` 是否存在。
5.  **缓存更新**：校验通过后，使用 `model_dump(mode='json')` 序列化（确保 datetime 转为 ISO 字符串），存入 Redis `template:{id}`。

> **ARCH-S2-001 修复**（2026-04-28）：原来使用 `datetime.now().isoformat()` 设置字符串类型导致类型不匹配，并且 `model_dump()` 不能直接 json.dumps。改为 datetime 对象 + `model_dump(mode='json')` 双重修复。

## MVP-02-T04: OpenMOSSClient 封装

### 1. 模块定位
`OpenMOSSClient` 是 Backend 与 OpenMOSS 交互的唯一桥梁。

### 2. 核心设计
*   **基础通信**：使用 `httpx.AsyncClient` 进行异步 HTTP 请求。
*   **认证管理**：集成 `TokenManager`，根据操作角色自动注入 `Authorization: Bearer <token>`（已修复为标准 Bearer 格式）。
*   **重试机制**：引入 `tenacity` 库，对网络错误进行指数退避重试（最多 3 次）。

### 3. 接口定义与状态机约束（ARCH-S2-002 修复更新）

**OpenMOSS 子任务状态机**：
```
pending → assigned（创建时设置 assigned_agent 或 planner reassign）
assigned/rework → in_progress（executor start，需传 session_id）
in_progress → review（executor submit，无需 session_id）
review → done（reviewer complete）
review → rework（reviewer rework）
任意非终态 → blocked（patrol block）
```

| 方法 | 对应 API | 角色 | 前置状态 | 说明 |
|:---|:---|:---|:---|:---|
| `create_sub_task` | `POST /api/sub-tasks` | Planner | - | 创建子任务 |
| `get_sub_task` | `GET /api/sub-tasks/{id}` | Planner | - | 获取详情 |
| `list_sub_tasks` | `GET /api/sub-tasks` | Planner | - | 列表查询 |
| `start_sub_task` | `POST .../start` | Executor | assigned/rework | 开始执行，需传 session_id |
| `submit_sub_task` | `POST .../submit` | Executor | **in_progress** | 提交成果，**无需** session_id |
| `complete_sub_task` | `POST .../complete` | Reviewer | review | 审查通过 |
| `rework_sub_task` | `POST .../rework` | Reviewer | review | 驳回返工 |
| `block_sub_task` | `POST .../block` | Patrol | 任意非终态 | 标记阻塞 |

```python
async def create_agent(self, name: str, model: str, workspace: str) -> Dict[str, Any]:
    """通过 Docker Exec CLI 创建 Agent"""
    cmd = [
        "docker", "exec", self.container_name, 
        "openclaw", "agents", "add", name, 
        "--model", model,
        "--workspace", workspace
    ]
    
    proc = await asyncio.create_subprocess_exec(
        *cmd,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE
    )
    stdout, stderr = await proc.communicate()
    
    if proc.returncode == 0:
        return {"status": "success", "name": name}
    else:
        return {"status": "error", "error": stderr.decode().strip()}
```

### 1. 业务场景与设计逻辑

### 2. YAML 动态任务节点设计

#### 2.1 动态任务节点完整结构

```yaml
tasks:
  - task_id: "dev-breakdown"
    name: "开发任务分解"
    type: dynamic                      # 🔑 动态任务类型
    
    dependencies: ["req-analysis"]     # 依赖需求分析完成
    
    target_role: "tech-lead"           # 技术负责人角色
    required_capabilities: ["task_decomposition", "architecture_design"]
    required_skills: ["decomposer-skill", "json-validator"]
    
    execution_context:
      instruction: |
        请根据需求文档（${req-analysis.output}），将开发任务分解为具体的子任务。
        
        要求：
        1. 每个子任务必须是原子性的（可在 2-4 小时内完成）
        2. 明确子任务之间的依赖关系
        3. 为每个子任务分配角色（backend/frontend/database）
        4. 输出合法的 JSON 数组
      
      input_mapping:
        requirement_doc: "${req-analysis.output}"
        tech_stack: "${input.tech_stack}"
      
      output_format: "json"
    
    output_definition:
      type: "json"
      schema:
        type: array
        items:
          type: object
          properties:
            name: {type: string}
            role: {type: string, enum: ["backend", "frontend", "database", "devops"]}
            instruction: {type: string}
            dependencies: {type: array, items: {type: string}}
            acceptance_criteria: {type: array, items: {type: string}}
          required: ["name", "role", "instruction"]
    
    control:
      timeout: 600                     # 10 分钟超时
      retry_policy:
        max_retries: 3                 # JSON 解析失败最多重试 3 次
```

### 4. 核心实现逻辑

#### 4.1 Decomposer 类设计

```python
# app/core/decomposer.py
import json
import re
import logging
import networkx as nx
from typing import List, Dict, Any

from app.clients.openmoss_client import openmoss_client
from app.core.template_loader import render_template

logger = logging.getLogger(__name__)


class Decomposer:
    """动态任务分解器"""
    
    def __init__(self):
        self.max_retries = 3
    
    async def decompose_task(
        self,
        task_def: Dict[str, Any],
        context: Dict[str, Any]
    ) -> List[Dict[str, Any]]:
        """
        执行动态任务分解
        
        Args:
            task_def: YAML 中的任务定义
            context: 运行时上下文（包含前置任务输出）
        
        Returns:
            子任务列表
        """
        # 1. 渲染指令
        instruction = render_template(
            task_def["execution_context"]["instruction"],
            context
        )
        
        # 2. 调用 LLM 分解（容错重试）
        max_retries = task_def.get("control", {}).get("retry_policy", {}).get("max_retries", 3)
        
        for attempt in range(max_retries):
            try:
                # 2.1 调用 LLM
                response = await self._call_llm(instruction)
                
                # 2.2 解析 JSON
                sub_tasks = self._parse_json(response)
                
                # 2.3 Schema 校验
                self._validate_schema(sub_tasks, task_def.get("output_definition", {}).get("schema"))
                
                # 2.4 DAG 校验
                self._validate_dag(sub_tasks)
                
                logger.info(f"Task decomposition succeeded on attempt {attempt + 1}")
                break
                
            except (JSONParseError, SchemaValidationError, DAGValidationError) as e:
                logger.warning(f"Decomposition attempt {attempt + 1} failed: {e}")
                
                if attempt == max_retries - 1:
                    raise DecompositionFailed(f"Failed after {max_retries} attempts: {e}")
                
                # 重试：将错误信息发回 LLM
                instruction = self._build_retry_instruction(e, response)
        
        # 3. 注入元数据
        sub_tasks = self._inject_metadata(sub_tasks, task_def)
        
        return sub_tasks
    
    def _parse_json(self, response: str) -> List[Dict]:
        """解析 JSON（容错处理）"""
        # 1. 提取 Markdown 代码块
        match = re.search(r'```json\s*\n(.*?)\n```', response, re.DOTALL)
        if match:
            json_str = match.group(1)
        else:
            # 2. 查找第一个 [ 和最后一个 ]
            start = response.find('[')
            end = response.rfind(']')
            if start == -1 or end == -1:
                raise JSONParseError("No JSON array found")
            json_str = response[start:end+1]
        
        # 3. 解析
        try:
            return json.loads(json_str)
        except json.JSONDecodeError as e:
            raise JSONParseError(f"Invalid JSON: {e}")
    
    def _validate_dag(self, sub_tasks: List[Dict]):
        """DAG 循环依赖检测"""
        graph = nx.DiGraph()
        
        for task in sub_tasks:
            task_id = task.get("name")
            graph.add_node(task_id)
            
            for dep in task.get("dependencies", []):
                graph.add_edge(dep, task_id)
        
        if not nx.is_directed_acyclic_graph(graph):
            cycle = nx.find_cycle(graph)
            raise DAGValidationError(f"Circular dependency detected: {cycle}")
```

```python
import re
from typing import Dict, List


def parse_description(description: str) -> Dict:
    """解析 description 中的元数据"""
    result = {
        'required_skills': [],
        'instruction': '',
        'output_format': 'text'
    }
    
    # 1. 提取 Required Skills
    skills_match = re.search(r'## Required Skills\n(.*?)(?=##|$)', description, re.DOTALL)
    if skills_match:
        skills_text = skills_match.group(1).strip()
        result['required_skills'] = [
            line.strip('- ').strip()
            for line in skills_text.split('\n')
            if line.strip()
        ]
    
    # 2. 提取 Instruction
    instruction_match = re.search(r'## Instruction\n(.*?)(?=##|$)', description, re.DOTALL)
    if instruction_match:
        result['instruction'] = instruction_match.group(1).strip()
    else:
        result['instruction'] = description
    
    # 3. 提取 Output Format
    format_match = re.search(r'## Output Format\n(.*?)(?=##|$)', description, re.DOTALL)
    if format_match:
        result['output_format'] = format_match.group(1).strip()
    
    return result
```

```python
# /skills/agency-agent/loader.py
import os
from typing import List, Dict


class SkillLoader:
    """Skill 加载器"""
    
    def __init__(self, skills_dir: str = "/skills"):
        self.skills_dir = skills_dir
    
    def load_skills(self, skill_names: List[str]) -> List[Dict]:
        """加载所需 Skills"""
        loaded_skills = []
        
        for skill_name in skill_names:
            skill_path = os.path.join(self.skills_dir, skill_name, "SKILL.md")
            
            if os.path.exists(skill_path):
                with open(skill_path, 'r', encoding='utf-8') as f:
                    skill_content = f.read()
                
                loaded_skills.append({
                    'name': skill_name,
                    'content': skill_content,
                    'path': skill_path
                })
            else:
                print(f"Warning: Skill {skill_name} not found at {skill_path}")
        
        return loaded_skills
    
    def build_system_prompt(self, loaded_skills: List[Dict], instruction: str) -> str:
        """构建 System Prompt（包含 Skill 上下文）"""
        parts = []
        
        # 1. Agency Agent 基础指令
        parts.append("# Agency Agent\n")
        parts.append("你是一个任务执行 Agent，已加载以下 Skills：\n")
        
        # 2. 加载的 Skills
        for skill in loaded_skills:
            parts.append(f"\n## Active Skill: {skill['name']}\n")
            parts.append(skill['content'])
        
        # 3. 任务指令
        parts.append(f"\n## Current Task\n")
        parts.append(instruction)
        
        return "\n".join(parts)
```

### 1. 问题根因分析

经过对 OpenMOSS 官方源码、Docker 部署配置、Backend 派发机制的全面审查，发现 **Agent 执行层完全缺失**。

#### 1.1 OpenMOSS 的架构本质：纯 Pull 模型

OpenMOSS 官方源码是一个 **纯 REST API 服务**，只提供：
- 子任务 CRUD API（`/api/sub-tasks`）
- 状态流转 API（`claim` / `start` / `submit` / `complete` / `rework`）
- Agent 注册和查询 API

**OpenMOSS 本身不包含任何 Agent 执行进程、Cron 脚本或轮询机制。** 它的设计假设是：
- Agent 由 OpenClaw 的 cron 定时唤醒
- 唤醒后，Agent 使用 `task-cli.py` CLI 工具通过 HTTP API 与 OpenMOSS 交互
- 标准流程：`st mine` → `st claim <id>` → `st start <id>` → 执行 → `st submit <id>`

#### 1.2 Backend SyncEngine 轮询机制（✅ 已实现）

```python
# app/core/sync_engine.py
async def start_sync_loop(self):
    """启动同步循环（后台任务）"""
    while True:
        await self.sync_all_tasks()  # 每 5 分钟轮询 OpenMOSS 状态
        await asyncio.sleep(self.sync_interval)  # 默认 300 秒
```

**SyncEngine 职责**：
- 每 5 分钟轮询 OpenMOSS 中所有进行中的子任务
- 同步状态到 Backend 数据库
- 如果任务完成（DONE），解锁后续依赖任务并调用 Dispatcher 派发

**SyncEngine 不职责**：
- ❌ 不唤醒 Agent 执行任务
- ❌ 不调用 OpenMOSS 的 claim/start/submit 接口

#### 1.3 断裂点分析

```
完整流程应该是:
  用户创建任务 → Backend 创建子任务 → OpenMOSS (status=assigned)
                                                    ↓
                                    Executor Agent (cron 唤醒)
                                                    ↓
                                    claim → start → 执行 → submit
                                                    ↓
                                    OpenMOSS (status=review)
                                                    ↓
                                    Reviewer Agent (cron 唤醒)
                                                    ↓
                                    complete → OpenMOSS (status=done)
                                                    ↓
                                    Backend SyncEngine (下次轮询发现 done)
                                                    ↓
                                    解锁后续依赖任务 → Dispatcher 派发下一个

实际断裂点:
  Backend 创建子任务 → OpenMOSS (status=assigned) ✅
                                    ↓
                          ❌ 没有 Executor Agent 的 cron 配置
                          ❌ 没有 executor 角色的 Agent 提示词
                          ❌ task-cli.py 的 BASE_URL 硬编码
                                    ↓
                          子任务永远停在 assigned 状态
```

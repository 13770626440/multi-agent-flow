# Agent Orchestrator - 多智能体协同编排器

## 概述

本 Skill 提供多智能体协同工作能力，支持三个组织的独立或协同工作：
- **技术评审组**：方案可行性评审、官方文档验证、关键技术点测试
- **测试组**：测试用例设计/执行、基于验证标准评判结果
- **开发组**：前后端开发/部署、每个函数的单元测试

## 触发指令

当用户说出以下指令时，自动激活本 Skill：
- "启动技术评审组"
- "启动测试组"
- "启动开发组"
- "启动技术评审组和测试组协同评审"
- "启动架构师组"
- "启动测试组和执行测试"

## 组织架构

| 组织 | 角色 | 核心职责 |
|:---|:---|:---|
| **技术评审组** | 架构师 1 + 架构师 2 | 方案可行性评审、官方文档验证、关键技术点测试 |
| **测试组** | 测试工程师 + QA | 测试用例设计/执行、基于验证标准评判结果 |
| **开发组** | 开发工程师 + 单元测试工程师 | 前后端开发/部署、每个函数的单元测试 |

## 核心原则

### 技术评审组
> ⚠️ **严禁猜测、臆想、欺骗**
> 关键技术点必须通过简单测试代码验证方案可行性

### 测试组
> ⚠️ **必须严格、如实、悲观地反馈测试结果**
> 测试用例必须包含：对应需求、测试目的、应用场景、输入输出、结果验证标准
> **严禁直接修改代码，只能反馈错误信息如日志、数据等**

### 开发组
> ⚠️ **要求单元测试全部通过，不遗留任何问题**
> 每个函数都必须有对应的单元测试，且测试通过
> **单元测试工程师只能测试代码开发，严禁修改功能源代码**

## 工作流程

### 单组工作

```
用户：启动技术评审组
  ↓
加载对应 Prompt 模板
  ↓
调用子 Agent 执行
  ↓
输出报告
```

### 多组协同

```
用户：启动技术评审组和测试组协同评审
  ↓
1. 启动技术评审组 → 输出评审报告
  ↓
2. 传递评审报告给测试组
  ↓
3. 启动测试组 → 输出测试报告
  ↓
4. 汇总两份报告 → 输出最终报告
```

## 输出格式

每个组织都有标准输出格式，详见：
- 技术评审组：`.agent-configs/architect-reviewer.md`
- 测试组：`.agent-configs/test-engineer.md`
- 开发组：`.agent-configs/developer.md`

## 配置文件路径

所有配置文件位于项目根目录的 `.agent-configs/` 目录：
- `architect-reviewer.md` - 技术评审组 Prompt 模板
- `test-engineer.md` - 测试组 Prompt 模板
- `developer.md` - 开发组 Prompt 模板
- `README.md` - 索引文件

## 使用示例

### 示例 1：启动技术评审组

**用户**：启动技术评审组，评审 OpenMOSS 鉴权方案

**执行流程**：
1. 加载 `architect-reviewer.md` 模板
2. 传入评审对象：OpenMOSS 鉴权方案
3. 调用子 Agent 执行评审
4. 输出评审报告

### 示例 2：启动测试组

**用户**：启动测试组，执行 TC-E2E-005 到 TC-E2E-007

**执行流程**：
1. 加载 `test-engineer.md` 模板
2. 传入测试对象：TC-E2E-005 到 TC-E2E-007
3. 调用子 Agent 执行测试
4. 输出测试报告

### 示例 3：多组协同

**用户**：启动技术评审组和测试组协同评审故事线 2

**执行流程**：
1. 启动技术评审组 → 评审故事线 2 代码和文档
2. 获取评审报告
3. 传递评审报告给测试组
4. 启动测试组 → 执行故事线 2 测试用例
5. 获取测试报告
6. 汇总两份报告 → 输出最终报告

## 注意事项

1. **子 Agent 是临时执行的**，无法保持持久状态
2. **主 Agent 负责协调**多个子 Agent 之间的工作
3. **所有报告必须保存到文件**，便于追溯和回顾
4. **严禁猜测和臆想**，所有结论必须有依据
